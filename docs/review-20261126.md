### 1.1 Linux 上 POLLERR 后 fd 不再被 poll（已核对）

- 位置：libuv [遇 POLLERR 自停并只回调一次](<../cbaselib/3rd/libuv/src/unix/poll.c#L47-L52>)；[TCP DataIn 额度满或单轮 4 MiB 提前返回](<../cbaselib/net/src/oi_tcp_channel.cpp#L19-L32>)；旧 `SetEvents` 掩码不变就直接返回（修复后见 [SetEvents](<../cbaselib/net/src/oi_poll.cpp#L175-L197>)）。
- 触发：对端先灌入超过单轮上限、或超过接收额度的未读数据，再发 RST。`OnPoll` 带错误进来，`DataIn` 读满额度或单轮上限就返回，没有读到错误；libuv 这时已经停掉 handle，之后不再回调。业务再打开读关注时掩码没变，`SetEvents` 直接返回，handle 不会重新 start。
- 后果：只收不发的连接永远不关，会话、输入缓冲和 fd 泄漏；HTTP 客户端等这条连接只能拿到超时。Windows 走另一套 uv_poll 实现，不受影响（未单独核对其语义）。
- 修复：[OnPoll 出错后](<../cbaselib/net/src/oi_poll.cpp#L107-L116>) handle 已不活跃且读关注开着时按原掩码重开；读关注关着时不重开，等 `SetEvents` 恢复读时再开，避免满额时空转。`SetEvents` 在掩码相同但 handle 已停时也重新 start。

### 1.2 对端零窗口时已关闭会话不回收（已核对）

- 位置：[AllowSend](<../cbaselib/net/src/oi_channel.cpp#L18-L31>) 对关闭中的会话只打开写关注，靠下一次 IO 事件进入 `TryClose`。
- 触发：会话已关闭，写关注早已打开（待发数据发不出去），对端零窗口且不再发数据。没有读写事件，`TryClose` 永远不执行。
- 后果：通道、最多 64 MiB 未发数据和 fd 一直占着。
- 修复：`SetEvents` 对已关闭会话挂 10 秒一次性定时器，到点兜底 `TryClose`（[ArmCloseReclaim](<../cbaselib/net/src/oi_poll.cpp#L119-L147>)），新增 [Channel::SessionClosed](<../cbaselib/net/src/oi_channel.cpp#L79-L82>)。定时器随 watch 一起关闭。

## 2. P2：只记录

### 2.1 UDP 来源地址数量无上限

- 位置：[OpenUdpPeerLocked](<../cbaselib/net/src/oi_session_manager.cpp#L460-L487>) 每个新来源 dup 一个 fd 并建会话；[空闲超时默认 60 秒](<../cbaselib/net/src/oi_session_manager.cpp#L34-L44>)才回收。
- 触发：UDP 口收到大量不同（可伪造）来源地址的报文。
- 后果：进程 fd 被耗尽，波及同进程其他连接；dup 失败的 `LOG_ERROR` 不限频。
- 严重度：取决于 UDP 口是否面向不可信网络，当前回归只在内网使用。
- 方向：每个管理器设 peer 数上限并限频日志；或改用绑定套接字 `sendto`，去掉每个 peer 一个 dup。排进 [todonext C](<../todonext.md#c-低内存极端配置与调用约束>)。

## 3. P3

1. **注册中心接管时断开误删旧登记**：新会话接管同一实例、[等 Redis 期间断开](<../cbaselib/registry/src/registry_server.cpp#L613-L624>)，补删走 [kWithdrawLua](<../cbaselib/registry/src/registry_server.cpp#L54-L57>)。此时 owner 已是新令牌，删掉的是仍在线旧会话的登记；旧服务短暂下线，下一次心跳失败后重登自愈。置信度：代码路径确认，未实测。方向：补删前确认没有别的会话因这次接管被标 superseded，或撤销接管标记。
2. **owner 丢失的新触发路径（并入已知项）**：[kRegisterLua](<../cbaselib/registry/src/registry_server.cpp#L37-L42>) 在同会话重登（`ARGV[6]=='1'`）且 owner 为 nil 时也返回 0，服务端回 EXIST，客户端 `m_bLost` 永久停登。与 [recheck §1.3](<review-20261125-recheck.md#13-registry-owner-键单独丢失被当成被占用客户端永久停登>) 的 [kRefreshLua](<../cbaselib/registry/src/registry_server.cpp#L45-L51>) 同根，修 §1.3 时两段 Lua 要一起改。
3. **注册客户端登记回包与断线交错**：[登记分支](<../cbaselib/proto/src/oi_registry_client.cpp#L488-L493>) 回包到达、协程恢复前旧连接断开，`OnDelSession` 已清 `m_bRegistered`，这里又写回 true；下一次心跳失败才重登，多下线约一个心跳。方向：同 [Publish](<../cbaselib/proto/src/oi_registry_client.cpp#L896>) 核对 sid 未变且仍连接。置信度：代码路径确认。
4. **日志标题数据竞争**：[Init](<../cbaselib/logger/src/oi_log.cpp#L59-L70>) 先 `StartClient` 后 `InitTitle`，多线程下其他线程可能已在[拼标题](<../cbaselib/logger/src/oi_log.cpp#L94-L95>)时读 `sLogTitle`。属 UB；推测实际通常只是标题错乱。方向：`InitTitle` 提到 `StartClient` 之前。
5. **RPC BUSY 回执发送失败后同批帧仍派发**：[BUSY 回执发送失败就 CloseSession](<../cbaselib/proto/src/oi_rpc_call.cpp#L646-L655>)，但 [OnDataIn 循环](<../cbaselib/proto/src/oi_rpc_session.cpp#L95-L139>) 不检查关闭，同批后续帧照样启动处理。后果：已关闭连接上的请求仍执行，回包丢弃。方向：循环里 `IsClosed()` 后 break。置信度：代码路径确认。
6. **PeerConnection 建连失败一次就把暂存请求全部回 CONNECT**：[Finish](<../cbaselib/proto/src/oi_rpc_peer.cpp#L229-L281>) 失败时交换出全部暂存请求逐个以 `OI_ERR_CONNECT` 唤醒，再排重连。与 [coroutine.md 单向消息](<coroutine.md#单向消息>)、[registry.md](<registry.md#L118>) 的「暂存，重连成功再补发」不符。需先定合同：改实现保留到重连或超时，或改文档。
7. **redisserver 轮转计数有符号溢出（已核对声明）**：[OnAddSession](<../modules/redisserver/src/redis_server.cpp#L335-L345>) 对 `int32_t` 的 [m_iNext](<../modules/redisserver/inc/redis_server.h#L42>) 无限 `++`，2^31 次连接后溢出 UB；回绕成负数后 `m_iNext % size` 为负，[Issue](<../modules/redisserver/src/redis_server.cpp#L486-L491>) 判越界直接关闭，新下游全部被拒（`connections>1` 时）。方向：改无符号或取模回绕。
8. **HTTP**：
   - a) **客户端断开后 handler 才完成，流式回复源不取消**：[完成回调](<../cbaselib/http/src/oi_http_server.cpp#L639-L646>) 按 sid 找不到会话时直接析构 `Completion`，`pBodySource` 不进 `m_pSource`，[OnClose 的 Cancel](<../cbaselib/http/src/oi_http_server.cpp#L692-L700>) 也轮不到它。是 [recheck §2.4](<review-20261125-recheck.md#24-http>) 的新触发路径。
