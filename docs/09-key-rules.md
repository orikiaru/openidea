# 关键规则

适用于自有基础库、模块和测试代码；第三方库、系统兼容接口保持原约定。成员、参数和局部变量命名见项目 AGENTS.md；类私有成员使用 `m_`，结构体和 rpcdata 成员不新增该前缀。

## 1. 逻辑简洁性

- 实现复杂度与业务影响相称，优先复用现有接口，避免为简单需求增加一致性系统或多层封装。
- 配置表尽量单次遍历；可选配置使用明确默认值，必需配置缺失立即报错。按已有配置或明确的枚举范围遍历，不硬编码枚举值清单，不假设枚举连续。

## 3. 错误处理

- 状态码统一 `int32_t`：0 成功，非 0 失败；遇错尽早返回。
- 复用具体错误码，避免用一个通用错误掩盖所有原因。RPC 负数保留给框架错误，正数用于业务错误；保持统一回执和调用接口。

## 5. 协议注册

- 使用命名处理函数，并在模块初始化中通过 `OI_RPC_BIND` 注册；按现有生成协议关联请求和响应，不另建配对逻辑。

## 6. Lambda 捕获

- 必须显式列出捕获项，禁止默认捕获 `[&]`、`[=]`，包括带额外捕获项的默认捕获形式。
- 优先按值捕获。使用引用捕获前必须向用户确认生命周期安全；捕获裸 `this` 或指针不代表延长对象寿命。
- 异步任务、协程跨挂起点必须保证捕获对象仍有效；按框架约定保活闭包，不能直接等待临时的带捕获协程 lambda。

## 7. 容器迭代

- 范围 for 使用 `auto&` / `const auto&`，禁止隐式复制元素。
- map 优先使用引用结构化绑定，解引用的元素/绑定名按实际类型命名，例如 `const auto& [sKey, stValue]`。
- 无删除、位置操作或手动推进需求时使用范围 for；保留的迭代器用 `auto`，名称允许 `it`、`nextIt`，不强制类型前缀。JSON 成员名等专属接口可保留显式迭代。

## 8. 避免成员遮蔽

- 参数、局部变量不得与成员同名。名字已经有语义的不再加 `Param`。去掉后只剩类型前缀、不成词的，保留 `Param`，如 `iParam`、`sParam`、`stParam`。和成员或已有局部变量撞名时，参数用 `Local` 后缀。RPC 宏参数固定为 `stRequest`、`stResponse`、可选 `stContext`。
- 构造函数初始化列表允许 `: iPriority(iPriority)`，冒号左边是成员。函数体不能自赋值，不用 `this->` 掩盖。改名后跑真实业务回归。

## 9. 业务词汇沿用项目约定

- 先核对本模块术语。阵容统一使用 `Arrange`，新增类型、字段、变量、函数和测试名不使用 `Lineup`。
- 改名同步生成绑定及使用方，保持既有协议字段号、类型和默认值。已有数据库/Redis key、JSON 键、配置键及外部文本契约不能仅为统一拼写而迁移；确需变更时单独设计兼容方案，涉及客户端协议时检查配套版本。
