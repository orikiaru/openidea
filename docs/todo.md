# 待办

## 单线程下的阻塞任务

需求：协程里要执行一段会阻塞的操作（文件、第三方同步 SDK 等），交给独立线程去跑，跑完把结果交回协程，不卡住 poll。

现状：

- 多线程可以直接在协程里调用阻塞函数，代价是占住一个协程工人线程，暂时够用。
- 单线程做不到。单线程编译下 `oi_lock.h` 的锁全是空实现，`StScheduler::Post` 和 `Poll::PostOnLoop` 的队列都不能从别的线程写；`ThreadPool::CreateSpecThread` 在单线程下直接断言失败。

大致方向（未定）：

- 对外提供 `co_await OI::Coro::RunBlocking(函数)`，返回函数结果，异常原样带回。
- 阻塞线程用固定数量的小线程池，线程数走 `[ThreadPool]` 配置，停止时统一 join，不按调用临时开线程。
- 完成后按 RPC 等待器的完成门写法交回：结果先写进堆上共享状态，再判断协程是否已挂起，挂起了才调度。
- 单线程需要在 `oi_lock.h` 补一把单线程下也生效的锁，保护跨线程投递队列，并用 `uv_async_send` 唤醒正在 `PollWait` 的主线程。单线程和多线程两套一起补，不在业务代码里绕开。
- 需要按协程类改动跑 Linux、Windows 的单线程和多线程回归。
