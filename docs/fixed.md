## 2026-11-21 审查问题修复

以下记录本轮实现和已观察的业务验证。跨平台、线程模式的完整验收结果另见测试记录；未列出未运行的场景。

- **TLS 密文背压**：发送额度不足时保留尚未入队的密文，额度释放后继续发送，不把 BUSY 写成永久错误。握手已完成但密文仍未入队时，新明文先进入待发缓冲，不把这次发送判失败。HTTPS 真实收发覆盖受限发送额度和 65536 字节正文，核对原请求完整回包；不代表所有 TLS 失败路径均被注入。
- **RPC 收包异常**：分发抛异常时记录原因并关闭受影响的流连接，避免继续使用不完整批次。故障注入时两个请求同时在途，首个调用失败、延迟响应的第二个调用得到断连错误，连接关闭且保护计数归零（`first=1/-1 second=1/-3 close=1 guard=0`）；测试未证明两个回包处在同一次接收批次。
- **连接补发异常**：逐项隔离待发请求的发送和完成回调异常，后续待发项及重试决策仍执行。注入完成回调异常后 8 项均得到完成，保护计数归零。
- **注册中心断线与重载交错**：按 owner 排除已经撤销的旧登记，并保留重载期间新登记和其他来源的数据。真实 Redis 代理交错测试核对撤销失败与重载后 Pull：旧 owner 不再出现，其他来源地址仍可见。
- **注册中心地址分隔校验**：登记前拒绝含空白的地址字段，避免空格分隔的存储格式被拆错；测试检查拒绝及原快照不变。
- **logd 跨日顺序**：日志和轮转标记按接纳顺序入各级队列，写线程先处理旧批次再切换。Linux 的虚拟时钟加慢写回归逐行核对日期目录与标题；同一用例在旧实现下观察到旧日标题落到新日目录。
- **logd 跨日磁盘操作**：建目录、打开、刷新和关闭在写线程完成。新文件打不开时留下原因并继续写当前文件，进程不退出；旧文件刷新或关闭失败仍停止进程。Linux 注入次日路径为普通文件，确认进程仍在且 stderr 有失败原因，再正常停掉。另用受控慢打开闸门期间发真实畸形帧，观察 poll 处理并关闭连接，放行后核对会话日志落盘。这两项注入目前仅 Linux 覆盖。
- **HTTP 流与半帧计时**：流的无进度使用独立空闲时限，不再把流式处理按普通半帧计时；回归让 sink BUSY 800 毫秒跨过 500 毫秒半帧时限，并核对最终响应。持续无进度与持续进度按各自计时语义处理。
- **HTTP 服务端空闲连接**：首字节前和完整响应后的空闲连接按独立空闲时限关闭，真实连接回归分别验证两种情况；活动处理和待发送数据不按普通空闲关闭。
- **HTTP 客户端 trailer 上限**：缓冲式 chunked 响应累计检查 trailer 上限，回归覆盖边界和超限，并检查调用结果。
- **HTTP 客户端畸形头**：无冒号的响应头按协议错误拒绝，回归同时检查错误结果和后续新连接。
- **HTTP 正文与接收容量**：普通请求正文增量消费，合法正文不再要求一次全部留在接收缓冲；回归在 131072 字节接收容量下，以普通固定长度和单 chunk 分别收发 524288 字节，并核对超限请求返回 413。
- **生成器声明与字段校验**：拒绝不支持的自由类型及非法声明、越界枚举，保留合法协议；生成器检查覆盖有效输入和错误输入，未把历史 `long` 的具体旧编码路径推断为已验证。
- **限定名 Bytes**：对裸名及已限定名分别生成正确类型，避免重复命名空间；生成器检查覆盖两种输入。
- **component 解析**：文本入口填充组件生成表，组件声明不再因缺表项误报；生成器检查包含合法和非法声明。

## 已修复：RPC 超时扫描异常隔离

超时扫描逐项捕获完成回调异常，继续完成同批等待者。回归登记 128 项同一截止时间的等待，首个回调确认同批至少还有一项后抛异常，检查所有结果为超时、128 次回调及 guard 归零。独立副本恢复旧行为后，Windows 多线程定向回归如预期失败，实得 `callbacks=1 same_batch=1 guard=127 bad=128`。

## 2026-11-21 修复

- **回归清理漏报服务崩溃**：`cleanup_owned` 逐进程核对退出码，非零即算清理失败；`disk-full` 的 logd 按预期非零保留例外。`test_test_safety` 增加对应用例。
- **单独构建的 webclient 线程模式**：`tools/build.py` 按 `--mode` 同步 `OI_WEBCLIENT_SINGLE_THREAD`。
- **双平台矩阵丢 Windows 自定义参数**：`test_matrix.py --platform both` 把 `--define` 同时传给 Windows 子命令。
- **并行矩阵中断遗留子进程**：`parallel_matrix.py` 在启动与等待外补 `try/finally`，只回收本进程拉起的 lane。
- **TCP 监听后登记失败不回滚**：`StartServer` 在 `Publish` 失败时调用 `AcceptChannel::StopAccept` 关掉监听并释放端口，析构走同一路径。`rpc-ingress` 用带点的服务名迫使登记在监听之后失败，核对退出码 `-6`、没有 `ipc server listen`，随后的正式进程绑上同一端口。
- **反向 Hold 分支无覆盖**：客户端注册 Hold 接收端并用 mark `-2147483598` 触发服务端反向调用，断言客户端 `hold reverse trigger ... bad=0`、`hold reverse request served delay=1000` 和服务端 `hold reverse reply bad=0`。

验证：以上改动随后在 2026-11-21 的四路 `--case all`（Windows MT/ST、WSL Linux MT/ST）中复测。登记失败回滚的注入、TLS 明文暂存和跨日打开失败保持进程，在同日稍后的四路全量（Windows MT/ST、远程 Linux MT/ST，22/22）里再核对过；结果见测试记录。

## HTTP 消息能力（已全部完成）

对照 [libhv HttpMessage.h](https://github.com/ithewei/libhv/blob/master/http/HttpMessage.h) 的消息接口，当前提供请求/响应、原始正文和可重复 header；不以接口名称相同或数量相等作为兼容承诺。以下按需求独立实施并保留既有接口，均已验收。

- [x] **Cookie**：提供解析与构造能力；以多个 Set-Cookie、大小写与空值、转义往返验收。Cookie 属性至少覆盖 domain、path、expires、max-age、secure、httponly 和 SameSite；自动 cookie jar 单独决策，不隐式跨请求保存。
- [x] **重复 query**：提供解析与构造能力，明确多值顺序及缺失值语义；以重复参数、空值和转义往返验收。
- [x] **URL 编码表单**：支持 `application/x-www-form-urlencoded`，明确重复字段、空值及尺寸上限；以真实服务往返、边界拆包和空字段验收。
- [x] **multipart 表单**：支持文本及文件字段，明确重复字段、二进制内容和尺寸上限；以真实服务往返、边界拆包、空字段和文件内容字节一致验收。JSON 继续使用现有 JsonCpp 和 rpcdata 能力。
- [x] **流式收发**：提供分段读取、写入及背压，定义取消、超时、断连和资源生命周期；以大文件分段收发、慢消费者、断连和内存上限验证。流式路由按片消费正文；普通缓冲路径仍按完整正文处理。
- [x] **客户端 HTTPS**：提供证书链和主机名校验；本地可信 CA、错误主机名、不受信任证书、握手超时与连接关闭由 Web 回归覆盖。证书管理与部署单独设计。

服务端 TLS 由 Nginx 等反向代理终止，代理与后端之间走 HTTP，本项目不实现服务端 TLS。

libhv 消息还提供文件、JSON、类型化值等便捷接口；是否引入以实际需求为准，不影响上述阶段的验收。

### P2

- **已修：明文 HTTP 传输错误被当成正常 EOF**。明文传输结束时保留底层错误，RST 等读错误返回连接错误，避免无长度响应被静默截断。
- **已修：Windows 端口占用预检失效**。TCP 生产监听使用 `SO_EXCLUSIVEADDRUSE`；回归预检对 TCP 和 UDP 分别独占探测回环及通配地址，覆盖已有普通和复用绑定。Linux TCP 保留 `SO_REUSEADDR`。
- **已修：注册中心同值重复登记后旧会话删除在线登记**。新登记接管旧绑定，Redis 租约使用独立 owner 令牌，撤销时仅删除自身租约；回归检查被接管连接的心跳和重复登记均返回占用，接管方心跳正常；旧连接关闭后地址、owner 和快照仍在，新连接关闭后清除，全新连接可以重新登记。
- **已修：定时器时间快照跨线程读写竞争**。四个 getter 均在锁内读取，时间结构按值返回。
- **已修：logd 延后帧缺单帧限额**。入队前检查帧及标题是否能放入待写预算，超限返回错误，不会让队首永久等待；现有回归覆盖合法帧背压与排空，超限帧边界尚未单独实测。
- **已修：HTTP 连接池在 EOF 处理前复用会话**。读到 EOF 时先标记连接不可复用，再交付已收到的数据，避免排队请求使用即将关闭的连接。
